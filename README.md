# Ward 119 Survey AI -> Live Civic Sheet (Django 5 + PostgreSQL)

A Django 5 + PostgreSQL web application for testing Telugu field interview transcription, structured extraction into Google-Sheet style problem rows live via Server-Sent Events (SSE), and fine-grained review where human analysts can tick (✓) or cross (✗) individual cells to audit and improve AI performance.

---

## Features

1. **Upload (`/`)**: Drag-and-drop or file selector for audio (`.mp3`, `.wav`, `.m4a`), dropdown of the 10 Ward 119 colonies, speaker name and phone number (recorded on every row), and prompt version picker.
2. **Live Run (`/run/<id>/`)**:
   - **Left panel**: Audio playback and live streaming Telugu transcript as generated by Gemini.
   - **Right panel**: Sheet rows appear one-by-one as each problem finishes, with live typewriter cell filling in column order.
   - Real-time updates via Server-Sent Events (`StreamingHttpResponse`). No Redis/Channels required. Auto-reconnects on disconnection.
3. **Sheet (`/sheet/`)**:
   - Full master table grouped by **Category > Sub-category**.
   - Every cell is editable inline (contenteditable) and autosaves with a 500ms debounce.
   - Filters by colony, speaker, and interview run.
   - **Quality flags**:
     - 🔴 **Red highlight**: Possible hallucinated/invented words (words not found in audio transcript).
     - 🟡 **Yellow highlight**: Cell is empty, but transcript contains related keywords.
   - **Export CSV**: UTF-8 with BOM (`\ufeff`) so Telugu characters open natively in Excel.
   - **Export JSON**: Complete structured JSON export for any interview run.
4. **Review (`/review/<id>/`)**:
   - Side-by-side view with audio player, full Telugu transcript, and "play this part" audio timestamp jump button.
   - Each row displays exact `source_quote` in Telugu.
   - Tick (✓) and Cross (✗) buttons on each cell.
   - Clicking Cross opens an error modal with taxonomy:
     - `wrong_transcription`
     - `wrong_category`
     - `wrong_split`
     - `invented_fact`
     - `missing_info`
     - `wrong_vote`
     - `wrong_level`
     - `wrong_cause`
     - `other`
     - Free note text.
   - Live summary bar showing total correct, flagged, and the most common error reason.
5. **Prompts (`/prompts/`)**: View, edit, and create prompt versions stored in PostgreSQL. Seed version 1 initialized from `gemini_prompt_ward119.md`.
6. **Compare (`/compare/`)**: Side-by-side run comparison for different prompt versions or interviews.

## Environment Variables

| Variable | Description | Default |
|---|---|---|
| `GEMINI_API_KEY` | Google Gemini API key (`google-genai` SDK) | `""` (mock stream mode used if omitted) |
| `GEMINI_MODEL` | Gemini model name | `gemini-2.5-flash` |
| `DATABASE_URL` | Neon or Supabase PostgreSQL connection string | SQLite (`db.sqlite3`) if unset |
| `SECRET_KEY` | Django secret key | `django-insecure-ward119-survey-secret-key-testing` |
| `APP_PASSWORD` | Shared password for simple single-password login | `ward119` |
| `DEBUG` | Enable/disable debug mode | `True` |
| `ALLOWED_HOSTS` | Comma-separated list of allowed hostnames | `*` |

## Local Setup

1. **Clone & install dependencies**:
   ```bash
   python -m venv venv
   source venv/bin/activate
   pip install -r requirements.txt
   ```

2. **Configure environment**:
   Create a `.env` file in the project root:
   ```env
   APP_PASSWORD=ward119
   GEMINI_API_KEY=your_gemini_api_key_here
   GEMINI_MODEL=gemini-2.5-flash
   # Optional: set DATABASE_URL for PostgreSQL; otherwise SQLite is used automatically
   # DATABASE_URL=postgresql://user:password@host/dbname?sslmode=require
   ```

3. **Run database migrations**:
   ```bash
   python manage.py migrate
   ```
   *(This automatically seeds the 10 Ward 119 areas and PromptVersion 1)*

4. **Run unit tests**:
   ```bash
   python manage.py test wardapp
   ```

5. **Start development server**:
   ```bash
   python manage.py runserver 0.0.0.0:8000
   ```
   Open `http://127.0.0.1:8000/` in your browser. Enter the password configured in `APP_PASSWORD` (default: `ward119`).

## How to Deploy on Render

1. **Create a Web Service on Render**:
   - Connect your GitHub repository.
   - **Environment**: `Python 3`.
   - **Build Command**:
     ```bash
     pip install -r requirements.txt && python manage.py collectstatic --noinput && python manage.py migrate
     ```
   - **Start Command**:
     ```bash
     gunicorn ward119.wsgi:application --bind 0.0.0.0:$PORT --workers 2 --timeout 120
     ```

2. **Add Environment Variables in Render Dashboard**:
   - `DATABASE_URL`: Your PostgreSQL connection string (Neon or Supabase).
   - `GEMINI_API_KEY`: Your Gemini API key.
   - `GEMINI_MODEL`: `gemini-2.5-flash`
   - `APP_PASSWORD`: Your secret shared app password.
   - `SECRET_KEY`: A strong random string.
   - `DEBUG`: `False`
   - `ALLOWED_HOSTS`: `your-app-name.onrender.com`

## How to Add or Iterate on Prompt Versions

1. Navigate to `/prompts/` in the web application.
2. Click **+ New Prompt Version**.
3. Enter a title (e.g. `Ward 119 v2.0 - Strict Vote Rules`) and paste your updated system prompt instructions.
4. When uploading a new audio file on `/`, select your newly created prompt version from the dropdown.
5. Compare the output side-by-side using `/compare/`.
